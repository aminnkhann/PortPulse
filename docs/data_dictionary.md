# Port-call event data dictionary — v1

The contract is a simplified synthetic ETA message, informed by the project proposal. It does not claim DCSA conformance. `scripts/event_model.py` defines the event fields and validation rules with Pydantic; ingestion validates each JSONL record with this model. The checked-in JSON Schema is generated from that model with `python -m scripts.event_model` for tools that consume JSON Schema. Do not edit the schema by hand.

| Field | Meaning | Contract rule |
|---|---|---|
| `event_id` | Non-empty stable event identity. Used for duplicate and collision detection. | Same ID and hash is an exact duplicate; same ID and a different hash is a collision. |
| `port_call_id` | Synthetic identity for the call being updated. The fixture uses one call: `PC-DEMO-001`. | A multi-call fixture is outside this first slice. |
| `source_id` | One of `coordinator_sim`, `carrier_sim`, or `terminal_sim`. | Unknown source IDs are rejected. |
| `event_time_utc` | When the source says it issued this update. ISO-8601 UTC string ending in `Z`. | Drives within-source ordering. |
| `received_at_utc` | Deterministic simulated platform receipt time, also ending in `Z`. | Drives freshness and delivery-delay calculations. |
| `ingested_at_utc` | Actual time PostgreSQL stores the event, generated by the database. | Separate from simulated receipt time; not used for ordering or ETA rules. |
| `eta_utc` | The predicted arrival time, not the update's creation time. ISO-8601 UTC string ending in `Z`. | Always required in v1. |
| `schema_version` | Contract version. The only supported value is `v1`. | The fixture's `v99` record exercises rejection. |
| `as_of_utc` | Fixed evaluation cutoff in the rules file, not an event field. | Events received after it are excluded. |
| canonical payload hash | SHA-256 over `event_id`, `port_call_id`, `source_id`, `event_time_utc`, `eta_utc`, and `schema_version`. | Excludes `received_at_utc` (transport metadata) and database-generated `ingested_at_utc`. |

## Reconciliation contract

- All data are generated by `scripts/generate_fixture.py`; no real port records are used.
- Events are JSON objects, one per JSONL line. Unknown fields and unsupported versions are rejected.
- Exact duplicate comparison uses the canonical payload hash fields above; received time may differ without changing source message identity.
- A collision invalidates every payload variant with that event ID.
- For each source, the latest eligible event time wins; ties use latest receipt time, then lexicographically smallest event ID.
- A source is stale only when `as_of_utc - latest_received_at` is greater than its configured threshold.
- Delayed delivery and conflict are flagged only when the difference is strictly greater than the configured threshold.
- The highest-priority fresh source wins. Conflicts compare each fresh source's latest ETA, even when one source wins by priority.
- Invalid, duplicate, collision, out-of-order, delayed, stale, and conflict conditions retain stable issue codes listed in the rules file.

## Database notes

- `raw_event` has a surrogate primary key and a unique constraint on `(event_id, canonical_payload_sha256)`. It can hold multiple distinct variants of a collided ID while collapsing exact payload duplicates.
- `quality_issue.event_id` is deliberately not unique or a foreign key: one ID can have multiple duplicate attempts or collision details, and malformed input may have no valid event row.
- `rejected_event` retains invalid payloads and a reason without requiring a valid source or port-call foreign key.
- `raw_event.ingested_at_utc` is assigned by PostgreSQL. Migration 003 backfills existing rows with its application time because their original ingestion time was not stored.
- Source priorities and freshness windows are seeded in `migrations/001_create_core_tables.sql` to match the rules file.

## Proposed Phase 2 mapping — Digitraffic Port Call V2

This mapping is a plan for a separate adapter; it does not change the synthetic v1 contract above. The API returns active visit snapshots from [Port Call V2](https://meri.digitraffic.fi/swagger/#/Port%20Call%20V2).

| PortPulse value | Digitraffic value | Handling |
|---|---|---|
| `port_call_id` | `visitId` | Stable identity for the visit. |
| `event_id` | `visitId` + `updateTime` | Identifies one source revision; canonical payload hash distinguishes exact repeats from ID collisions. |
| `source_id` | Constant `digitraffic` | Add it explicitly to the source configuration and validator. |
| `event_time_utc` | `updateTime` | Preserve its source meaning: when Digitraffic says the visit was updated. |
| `eta_utc` | `eta` | Validate as UTC before reconciliation. |
| `received_at_utc` | Time the adapter first receives this revision | Persist once; replays use the stored time and never refetch the API. |
| Source metadata | `status`, `portOfCall`, `vesselId`, `mmsi`, `vesselName` | Retain the raw response and selected fields for audit/query output. |

Repeated polling of an unchanged revision produces an exact duplicate. A changed `updateTime` is a new event in the same visit history. Different canonical content for the same derived `event_id` is an `ID_COLLISION`; exclude all variants of that ID from trusted state. If two sources disagree, record a conflict and choose only by the explicitly approved source priority, followed by the existing event-time and tie-break rules. No Digitraffic priority is assumed until the team records one in the source/rules configuration. The API's `updateTime` means visit update time; do not describe it as a precise ETA-message creation time.

For reproducible checks, save a small API response as a fixture and test the mapping, repeated-poll duplicate, revised visit, collision, conflicting source, and winner selection against that fixed input. Send the recommended `Digitraffic-User` header, follow request limits, and credit Fintraffic / Digitraffic under CC BY 4.0 if publishing results.
